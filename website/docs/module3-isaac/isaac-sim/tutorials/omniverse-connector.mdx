# Omniverse Connector Tutorial

## Introduction to Omniverse Connection

NVIDIA Omniverse is a simulation and collaboration platform that enables real-time collaboration between teams and applications. Isaac Sim connects to Omniverse to provide shared simulation environments, asset libraries, and collaborative development capabilities.

This tutorial covers connecting Isaac Sim to Omniverse, sharing assets, and collaborating on simulation environments with team members.

## Prerequisites

Before starting this tutorial, ensure you have:
- Access to an Omniverse server (Nucleus)
- Isaac Sim installed and running
- Network access to the Omniverse server
- Valid credentials for the Omniverse server

## Setting Up Omniverse Connection

### 1. Configuring Omniverse Nucleus Connection

Omniverse Nucleus is the asset management and collaboration server that connects different Omniverse applications:

1. **Configure Nucleus Connection**:
   - Launch Isaac Sim
   - Go to "Window" > "Omniverse" > "Connection"
   - Enter the Nucleus server URL (e.g., `omniverse://server.example.com`)
   - Enter your username and password
   - Click "Connect"

2. **Verify Connection**:
   - Check that you can see the contents of the Omniverse file system
   - Verify that you can browse shared libraries and assets

### 2. Understanding Omniverse Paths

Omniverse uses special paths to identify assets:

- `omniverse://server_name.usd_path` - Access assets on Omniverse server
- `Library://` - Shared asset libraries
- `Projects://` - User project directory
- `Assets://` - User asset directory

## Connecting Isaac Sim to Omniverse

### Using the Connect Tab

1. In Isaac Sim, click on "Window" > "Omniverse" > "Connect"
2. Enter your server connection details in the Connect tab
3. Authenticate with your credentials
4. Browse available assets and projects in the Asset Browser

### Configuring Auto-Connection

For regular use, you can configure automatic connection to Omniverse:

```python
# Example: Configure Omniverse connection programmatically
import carb
import omni

def setup_omniverse_connection(server_url, username, password):
    """
    Configure Omniverse connection settings
    """
    # Set connection parameters
    carb.settings.get_settings().set("/exts/omni.kit.connect/service/active", True)
    carb.settings.get_settings().set("/exts/omni.kit.connect/service/server_url", server_url)
    carb.settings.get_settings().set("/exts/omni.kit.connect/service/username", username)
    
    # Connect to Omniverse
    omni.kit.connect.ConnectAPI.get_instance().connect(username, password)
```

## Collaborative Simulation Workflows

### Version Control in Omniverse

Omniverse provides basic version control for assets:

1. **Check Out**: When editing an asset, check it out to prevent conflicts
2. **Check In**: After editing, check in the asset with a descriptive comment
3. **Review Changes**: Compare your changes with the previous version
4. **Resolve Conflicts**: If multiple people edit the same asset, resolve conflicts

### Real-Time Collaboration

For real-time collaboration:
1. Multiple users can open the same USD file simultaneously
2. Changes made by one user are visible to others (with some delay)
3. Use the chat feature in Omniverse to coordinate work
4. Use layer management to work on different aspects of a scene

## Working with Omniverse Assets

### Browsing and Using Shared Assets

To use shared assets in your simulation:

1. Open the Asset Browser (Window > Content > Library)
2. Navigate to the desired asset in Omniverse
3. Drag the asset into your current stage or scene
4. Modify properties as needed for your simulation

```python
# Example: Loading an asset from Omniverse
from omni.isaac.core.utils.stage import add_reference_to_stage
from omni.isaac.core.utils.nucleus import get_assets_root_path

def load_robot_from_omniverse(robot_name, prim_path):
    """
    Load a robot asset from Omniverse library
    """
    # Get the Omniverse assets root
    assets_root = get_assets_root_path()
    
    if assets_root is None:
        print("Could not connect to Omniverse Nucleus")
        return None
    
    # Construct path to the robot
    robot_path = f"{assets_root}/Robots/{robot_name}.usd"
    
    # Add reference to stage
    add_reference_to_stage(usd_path=robot_path, prim_path=prim_path)
```

## Troubleshooting Connection Issues

### Common Connection Problems

**Problem**: Cannot connect to Omniverse Nucleus server.
**Solutions**:
- Verify the server URL is correct
- Check network connectivity to the server
- Ensure you have valid credentials
- Verify that the Omniverse server is running

**Problem**: Asset fails to load from Omniverse.
**Solutions**:
- Check that the asset path is correct
- Verify you have read permissions for the asset
- Ensure all referenced assets exist in Omniverse
- Check that the asset is not corrupted

**Problem**: Slow asset loading from Omniverse.
**Solutions**:
- Verify network connection speed
- Check Omniverse server performance
- Consider using local copies of frequently used assets
- Optimize asset file sizes

### Performance Optimization

**Optimize Asset Loading**:
- Use proxy geometry for complex assets during scene assembly
- Implement streaming for large environments
- Use level-of-detail (LOD) for distant objects
- Cache frequently accessed assets locally

                editor_menu.remove_item(self._menu_item)
        
        self._ext_id = None
