# USD Workflows in Isaac Sim

## Understanding USD

Universal Scene Description (USD) is the core technology underlying NVIDIA Isaac Sim. Developed by Pixar, USD is a powerful schema for describing, composing, simulating, and rendering 3D scenes. In Isaac Sim, USD not only represents the 3D geometry but also includes physics properties, materials, animations, and simulation states.

Understanding USD workflows is essential for effectively using Isaac Sim for complex robotics simulation tasks.

## USD Core Concepts

### Stage, Prims, and Properties

The fundamental components of USD are:

- **Stage**: Top-level container that represents the entire scene
- **Prims**: USD scene objects (primitives) that can contain properties and relationships
- **Properties**: Values associated with prims, describing their attributes and relationships

```python
# Example: Basic USD operations in Isaac Sim
from pxr import Usd, UsdGeom, Gf
import omni

# Get the current stage in Isaac Sim
stage = omni.usd.get_context().get_stage()

# Create a new Xform prim (transform node)
xform = UsdGeom.Xform.Define(stage, "/World/MyRobot")

# Add a mesh as a child of the Xform
mesh = UsdGeom.Mesh.Define(stage, "/World/MyRobot/Body")
mesh.CreatePointsAttr([(-1, -1, 0), (1, -1, 0), (1, 1, 0), (-1, 1, 0)])
mesh.CreateFaceVertexIndicesAttr([0, 1, 2, 0, 2, 3])
mesh.CreateFaceVertexCountsAttr([3, 3])
```

### Composition

USD's composition system allows for powerful scene assembly:

- **References**: Include other USD files as components
- **Payloads**: Lazy-load heavy content
- **Layers**: Stack multiple scene descriptions
- **Variants**: Switch between different versions of the same asset

## Common USD Workflows in Isaac Sim

### 1. Creating and Modifying Scenes

#### Loading an Existing USD File

```python
# Load a USD file into Isaac Sim
from omni.isaac.core.utils.stage import open_stage
from omni.isaac.core.utils.stage import add_reference_to_stage

# Open an existing stage
open_stage(usd_path="path/to/your/scene.usd")

# Add a reference to an asset in your scene
add_reference_to_stage(
    usd_path="path/to/robot_asset.usd", 
    prim_path="/World/Robot1"
)
```

#### Creating a New Scene Programmatically

```python
# Example: Creating a new scene with a ground plane and robot
import omni
from pxr import UsdGeom, Gf
from omni.isaac.core import World
from omni.isaac.core.robots import Robot

def create_robot_scene():
    # Get the stage
    stage = omni.usd.get_context().get_stage()
    
    # Create a ground plane
    ground_plane = UsdGeom.Mesh.Define(stage, "/World/GroundPlane")
    # Create a large plane for the ground
    plane_points = [
        Gf.Vec3f(-10, -10, 0), Gf.Vec3f(10, -10, 0),
        Gf.Vec3f(10, 10, 0), Gf.Vec3f(-10, 10, 0)
    ]
    plane_faces = [0, 1, 2, 0, 2, 3]
    plane_counts = [3, 3]
    
    ground_plane.CreatePointsAttr(plane_points)
    ground_plane.CreateFaceVertexIndicesAttr(plane_faces)
    ground_plane.CreateFaceVertexCountsAttr(plane_counts)
    
    # Create a physics scene
    scene = UsdPhysics.Scene.Define(stage, "/World/physicsScene")
    
    # Add a robot to the scene
    # (This assumes you have a robot USD file)
    robot = Robot(
        prim_path="/World/MyRobot",
        name="my_robot",
        usd_path="path/to/robot.usd"
    )
```

### 2. Managing Assets with Composition

#### Using References

USD's referencing system allows you to maintain assets independently:

```python
# Example: Referencing a robot asset
from pxr import Sdf

# Create a new stage
stage = omni.usd.get_context().get_stage()

# Create an Xform that will contain the robot
robot_xform = UsdGeom.Xform.Define(stage, "/World/Robot1")

# Add a reference to the robot asset
robot_xform.GetPrim().GetReferences().AddReference(
    asset_path="path/to/robot.usd",
    prim_path="/Robot"  # Path within the referenced file to include
)
```

#### Using Variants

Variants allow you to store multiple versions of the same asset:

```python
# Example: Creating a robot with different configurations
from pxr import Usd, Sdf

stage = omni.usd.get_context().get_stage()

# Create a prim with variants
robot_xform = UsdGeom.Xform.Define(stage, "/World/MyRobot")
variant_set = robot_xform.GetPrim().GetVariantSet("Configuration")

# Add different configurations
variant_set.SetVariantSelection("Standard")
with variant_set.GetVariantEditContext("Standard"):
    # Define standard configuration
    add_standard_sensors(robot_xform)

variant_set.SetVariantSelection("Advanced")
with variant_set.GetVariantEditContext("Advanced"):
    # Define advanced configuration with more sensors
    add_advanced_sensors(robot_xform)
```

### 3. Working with Materials and Shading

USD includes a powerful material system called Universal Material (UsdShade):

```python
# Example: Adding materials to objects
from pxr import UsdShade, Sdf

def add_material_to_object(prim_path, color=(1.0, 0.0, 0.0)):
    """
    Apply a material with a given color to an object
    """
    stage = omni.usd.get_context().get_stage()
    prim = stage.GetPrimAtPath(prim_path)
    
    # Create a material
    material_path = Sdf.Path(f"{prim_path}/Material")
    material = UsdShade.Material.Define(stage, material_path)
    
    # Create a PBR shader
    shader_path = Sdf.Path(f"{material_path}/Shader")
    shader = UsdShade.Shader.Define(stage, shader_path)
    shader.CreateIdAttr("UsdPreviewSurface")
    
    # Set the color
    shader.CreateInput("diffuseColor", Sdf.ValueTypeNames.Color3f).Set(color)
    shader.CreateInput("metallic", Sdf.ValueTypeNames.Float).Set(0.0)
    shader.CreateInput("roughness", Sdf.ValueTypeNames.Float).Set(0.5)
    
    # Connect the shader to the material
    material.CreateSurfaceOutput().ConnectToSource(shader.ConnectableAPI(), "surface")
    
    # Apply the material to the prim
    UsdShade.MaterialBindingAPI(prim).Bind(material)
```

## Isaac Sim Specific USD Patterns

### Physics Prims

Isaac Sim uses USD Physics schema for physics properties:

```python
# Example: Setting up physics properties for objects
from pxr import UsdPhysics, PhysxSchema

def setup_physics_properties(prim_path):
    stage = omni.usd.get_context().get_stage()
    prim = stage.GetPrimAtPath(prim_path)
    
    # Apply collision API
    collision_api = UsdPhysics.CollisionAPI.Apply(prim)
    collision_api.GetApproximationAttr().Set("convexHull")
    
    # Apply rigid body API
    rigid_body_api = PhysxSchema.PhysxRigidBodyAPI.Apply(prim)
    rigid_body_api.GetEnableGyroscopicForcesAttr().Set(True)
    
    # Set mass properties
    mass_api = UsdPhysics.MassAPI.Apply(prim)
    mass_api.GetMassAttr().Set(1.0)
```

### Robot Articulation

Articulated robots require special USD setup:

```python
# Example: Setting up a robot articulation
from pxr import PhysxSchema

def setup_robot_articulation(robot_root_path):
    stage = omni.usd.get_context().get_stage()
    robot_prim = stage.GetPrimAtPath(robot_root_path)
    
    # Apply articulation root API to the robot root
    articulation_root_api = PhysxSchema.PhysxArticulationRootAPI.Apply(robot_prim)
    articulation_root_api.GetEnabledSelfCollisionsAttr().Set(False)
    
    # Apply joint properties to each joint (simplified example)
    # You would typically iterate through all joints in your robot
    joint_prim = stage.GetPrimAtPath(f"{robot_root_path}/joint1")
    joint_api = PhysxSchema.PhysxJointAPI.Apply(joint_prim)
```

## USD Performance Considerations

### Level of Detail (LOD)

For complex scenes, consider using LOD:

```python
# Example: Setting up LOD for complex objects
def setup_lod(prim_path, lod_paths):
    """
    Set up level of detail for an object
    :param prim_path: Path to the main prim
    :param lod_paths: List of paths to lod representations in decreasing detail
    """
    stage = omni.usd.get_context().get_stage()
    prim = stage.GetPrimAtPath(prim_path)
    
    # Create LOD group
    lod_group = UsdGeom.LOD.Define(stage, f"{prim_path}/LODGroup")
    
    # Define LOD thresholds (distances at which to switch to different geometry)
    distances = [0.0, 10.0, 20.0]  # Switch at 0m, 10m, and 20m
    lod_group.CreateLODsAttr(lod_paths)
    lod_group.CreateDistanceAttr(distances)
```

### Proxy Geometries

For performance, use proxy geometries for physics while keeping detailed visuals:

```python
# Example: Using proxy geometry for physics
def setup_proxy_geometry(visual_prim_path, collision_geom_path):
    stage = omni.usd.get_context().get_stage()
    visual_prim = stage.GetPrimAtPath(visual_prim_path)
    
    # Attach collision API to visual prim
    collision_api = UsdPhysics.CollisionAPI.Apply(visual_prim)
    
    # Use a different geometry for collision
    collision_api.GetCollisionEnabledAttr().Set(True)
    
    # The collision geometry can be simpler than the visual geometry
    # This is handled by the collision approximation settings
    collision_api.GetApproximationAttr().Set("convexHull")
```

## Troubleshooting USD Workflows

### 1. Scene Loading Issues

Problem: USD files fail to load or display incorrectly.
Solutions:
- Check USD file syntax with `usdcat` tool
- Verify that all referenced assets are available
- Ensure file paths are correctly formatted

### 2. Performance Issues

Problem: Scene is slow to load or update.
Solutions:
- Simplify complex geometries
- Use proxy geometry for physics
- Implement LOD for distant objects
- Reduce the number of active physics objects

### 3. Material Issues

Problem: Materials don't appear correctly.
Solutions:
- Ensure material definitions are properly linked to geometry
- Check that material paths are relative to the stage root
- Verify that material properties are compatible with Isaac Sim's renderer

## Best Practices

### 1. Asset Organization

- Keep related assets together in logical directory structures
- Use consistent naming conventions
- Version control USD files for reproducible scenes

### 2. Performance Optimization

- Keep stage complexity low for real-time performance
- Use instancing for repeated objects
- Avoid overly complex geometries
- Pre-compute static lighting where possible

### 3. Reusability

- Structure USD files for composition and reusability
- Use variants for different configurations of the same asset
- Maintain a library of standard components

## Advanced USD Techniques

### Custom Schemas

For specialized robotics applications, you might want to create custom USD schemas:

```python
# This is a simplified example - actual schema creation is more complex
class CustomRobotSchema:
    """Custom schema for robot-specific properties in USD"""
    
    @staticmethod
    def add_robot_properties(prim_path):
        stage = omni.usd.get_context().get_stage()
        prim = stage.GetPrimAtPath(prim_path)
        
        # Add custom attributes
        prim.CreateAttribute("robot:controlType", Sdf.ValueTypeNames.Token).Set("position")
        prim.CreateAttribute("robot:maxVelocity", Sdf.ValueTypeNames.Float).Set(1.0)
        prim.CreateAttribute("robot:operationalMode", Sdf.ValueTypeNames.Token).Set("autonomous")
```

### Animation and Simulation Data

USD can store animation and simulation data:

```python
# Example: Storing simulation data in USD
def store_simulation_data(prim_path, time_samples, poses):
    """
    Store robot pose data over time in USD
    """
    stage = omni.usd.get_context().get_stage()
    prim = stage.GetPrimAtPath(prim_path)
    
    # Create position attribute with time samples
    positions_attr = prim.CreateAttribute(
        "xformOp:translate", 
        Sdf.ValueTypeNames.Float3, 
        custom=False,
        variability=UsdGeom.Tokens.varying
    )
    
    # Set position at different time samples
    for time, pose in zip(time_samples, poses):
        positions_attr.Set(pose[:3], time=time)  # Extract position from pose
```
