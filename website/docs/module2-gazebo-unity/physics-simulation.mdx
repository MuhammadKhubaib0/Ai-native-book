# Physics Simulation in Gazebo

## Overview

Welcome to Module 2: The Digital Twin (Gazebo & Unity). This module builds upon the ROS 2 foundations from Module 1 and introduces you to physics simulation in Gazebo, sensor simulation, high-fidelity rendering in Unity, and sim-to-real transfer techniques.

In this first chapter, we'll cover the fundamentals of physics simulation in Gazebo, focusing on:
- Rigid body dynamics
- Contact models
- Gravity
- Collisions
- Friction parameters

Gazebo is a powerful physics simulation engine that provides realistic simulation of robots in complex environments. It's widely used in robotics research and development for testing algorithms before deploying them on real robots.

## Rigid Body Dynamics

Rigid body dynamics is the simulation of motion of solid objects that do not deform. In Gazebo, rigid bodies are defined using the Simulation Description Format (SDF), which is similar to URDF but designed specifically for simulation.

### Key Concepts

In rigid body dynamics, there are three fundamental concepts:

1. **Mass**: Resistance to acceleration when force is applied
2. **Inertia**: Resistance to rotational motion around an axis
3. **Forces**: External influences that cause acceleration

In SDF, these properties are defined in the `<inertial>` block:

```xml
<link name="my_link">
  <inertial>
    <mass>1.0</mass>
    <inertia>
      <ixx>0.01</ixx>
      <ixy>0.0</ixy>
      <ixz>0.0</ixz>
      <iyy>0.01</iyy>
      <iyz>0.0</iyz>
      <izz>0.01</izz>
    </inertia>
  </inertial>
</link>
```

### Newton's Laws in Simulation

Gazebo implements Newton's laws of motion:
1. An object at rest stays at rest, and an object in motion stays in motion
2. Force equals mass times acceleration (F = ma)
3. For every action, there is an equal and opposite reaction

## Gravity

Gravity is a fundamental force in physics simulation that affects all objects with mass. In Gazebo, gravity is defined in the world file as a vector:

```xml
<world name="default">
  <gravity>0 0 -9.8</gravity>
  <!-- rest of the world definition -->
</world>
```

The default gravity vector in Gazebo is [0, 0, -9.8] m/s², simulating Earth's gravity. This means objects will accelerate downward at 9.8 m/s².

## Collision Detection and Contact Models

Collision detection is the computational problem of detecting the intersection of two or more objects. In Gazebo, collision detection happens in two phases:

1. **Broad Phase**: Quickly eliminates pairs of objects that are far apart
2. **Narrow Phase**: Performs precise collision detection for pairs that might be colliding

### Contact Models

When objects collide, Gazebo uses contact models to determine the response. The most common model is the ODE (Open Dynamics Engine) contact model, which includes:

- **Bounce**: The coefficient of restitution (how bouncy the collision is)
- **Mu**: The coefficient of friction for the primary direction of contact
- **Mu2**: The coefficient of friction for the secondary direction of contact
- **Soft ERP**: Error reduction parameter for how much of an error is corrected each step
- **Soft CFM**: Constraint force mixing parameter that controls how soft a constraint is

An example of a collision definition in SDF:

```xml
<link name="my_link">
  <collision name="collision">
    <geometry>
      <box>
        <size>1 1 1</size>
      </box>
    </geometry>
    <surface>
      <friction>
        <ode>
          <mu>1.0</mu>
          <mu2>1.0</mu2>
        </ode>
      </friction>
      <bounce>
        <restitution_coefficient>0.1</restitution_coefficient>
        <threshold>100000</threshold>
      </bounce>
      <contact>
        <ode>
          <soft_cfm>0</soft_cfm>
          <soft_erp>0.2</soft_erp>
          <max_vel>0.01</max_vel>
          <min_depth>0</min_depth>
        </ode>
      </contact>
    </surface>
  </collision>
</link>
```

## Physics Engine Parameters

Gazebo supports multiple physics engines: ODE (default), Bullet, and DART. Each engine has specific parameters that affect the accuracy and performance of the simulation.

### ODE Parameters in World File

```xml
<physics type="ode">
  <max_step_size>0.001</max_step_size>
  <real_time_factor>1</real_time_factor>
  <real_time_update_rate>1000</real_time_update_rate>
  <ode>
    <solver>
      <type>quick</type>
      <iters>10</iters>
      <sor>1.3</sor>
    </solver>
    <constraints>
      <cfm>0.0</cfm>
      <erp>0.2</erp>
      <contact_max_correcting_vel>100.0</contact_max_correcting_vel>
      <contact_surface_layer>0.001</contact_surface_layer>
    </constraints>
  </ode>
</physics>
```

## Creating a Basic Physics World

Let's create a simple world file that demonstrates these concepts:

```xml
<?xml version="1.0" ?>
<sdf version="1.7">
  <world name="physics_demo">
    <!-- Include the default ground plane -->
    <include>
      <uri>model://ground_plane</uri>
    </include>

    <!-- Include a simple light source -->
    <include>
      <uri>model://sun</uri>
    </include>

    <!-- Define physics parameters -->
    <physics type="ode">
      <max_step_size>0.001</max_step_size>
      <real_time_factor>1</real_time_factor>
      <real_time_update_rate>1000</real_time_update_rate>
    </physics>

    <!-- Add a static box on the ground -->
    <model name="static_box">
      <static>true</static>
      <link name="link">
        <pose>0 0 0.5 0 0 0</pose>
        <collision name="collision">
          <geometry>
            <box>
              <size>1 1 1</size>
            </box>
          </geometry>
        </collision>
        <visual name="visual">
          <geometry>
            <box>
              <size>1 1 1</size>
            </box>
          </geometry>
        </visual>
      </link>
    </model>

    <!-- Add a dynamic sphere that will fall due to gravity -->
    <model name="falling_sphere">
      <link name="link">
        <pose>0 0 5 0 0 0</pose>
        <inertial>
          <mass>1.0</mass>
          <inertia>
            <ixx>0.1</ixx>
            <ixy>0</ixy>
            <ixz>0</ixz>
            <iyy>0.1</iyy>
            <iyz>0</iyz>
            <izz>0.1</izz>
          </inertia>
        </inertial>
        <collision name="collision">
          <geometry>
            <sphere>
              <radius>0.2</radius>
            </sphere>
          </geometry>
        </collision>
        <visual name="visual">
          <geometry>
            <sphere>
              <radius>0.2</radius>
            </sphere>
          </geometry>
        </visual>
      </link>
    </model>
  </world>
</sdf>
```

## Friction Parameters

Friction is the force that resists the relative motion of solid surfaces sliding against each other. In Gazebo, friction is primarily controlled through the `mu` and `mu2` parameters:

- **Mu (μ)**: The coefficient of friction in the primary direction (typically the direction of motion)
- **Mu2 (μ₂)**: The coefficient of friction in the secondary direction (perpendicular to the primary direction)

Values typically range from 0 (no friction) to values greater than 1 (very high friction). For example:
- Ice on ice: ~0.1
- Rubber on pavement: ~0.8
- Tire on road: ~0.7-0.9

## Practical Example: Setting Up Physics in a Custom World

Here's how to create a custom world with specific physics properties:

1. Create a new world file `physics_demo.world`:

```xml
<?xml version="1.0" ?>
<sdf version="1.7">
  <world name="custom_physics_world">
    <include>
      <uri>model://ground_plane</uri>
    </include>
    
    <include>
      <uri>model://sun</uri>
    </include>
    
    <!-- Setting custom gravity -->
    <gravity>0 0 -8.7</gravity>
    
    <!-- Physics engine configuration -->
    <physics type="ode">
      <max_step_size>0.001</max_step_size>
      <real_time_factor>1</real_time_factor>
      <real_time_update_rate>1000</real_time_update_rate>
      
      <ode>
        <solver>
          <type>quick</type>
          <iters>20</iters>
          <sor>1.3</sor>
        </solver>
        
        <constraints>
          <cfm>0.0</cfm>
          <erp>0.2</erp>
        </constraints>
      </ode>
    </physics>
    
    <!-- Add objects for physics demonstration -->
    <model name="ramp">
      <pose>0 0 0 0 0.5 0</pose>
      <link name="link">
        <collision name="collision">
          <geometry>
            <box>
              <size>3.0 1.0 0.2</size>
            </box>
          </geometry>
        </collision>
        <visual name="visual">
          <geometry>
            <box>
              <size>3.0 1.0 0.2</size>
            </box>
          </geometry>
          <material>
            <ambient>0.5 0.5 0.5 1</ambient>
            <diffuse>0.8 0.8 0.8 1</diffuse>
          </material>
        </visual>
        <inertial>
          <mass>100.0</mass>
          <inertia>
            <ixx>1.0</ixx>
            <ixy>0</ixy>
            <ixz>0</ixz>
            <iyy>1.0</iyy>
            <iyz>0</iyz>
            <izz>1.0</izz>
          </inertia>
        </inertial>
      </link>
    </model>
    
    <!-- A box that will slide down the ramp -->
    <model name="sliding_box">
      <pose>-1.0 0 1.5 0 0 0</pose>
      <link name="link">
        <collision name="collision">
          <geometry>
            <box>
              <size>0.4 0.4 0.4</size>
            </box>
          </geometry>
          <surface>
            <friction>
              <ode>
                <mu>0.1</mu>
                <mu2>0.1</mu2>
              </ode>
            </friction>
          </surface>
        </collision>
        <visual name="visual">
          <geometry>
            <box>
              <size>0.4 0.4 0.4</size>
            </box>
          </geometry>
          <material>
            <ambient>1 0 0 1</ambient>
            <diffuse>1 0 0 1</diffuse>
          </material>
        </visual>
        <inertial>
          <mass>1.0</mass>
          <inertia>
            <ixx>0.015</ixx>
            <ixy>0</ixy>
            <ixz>0</ixz>
            <iyy>0.015</iyy>
            <iyz>0</iyz>
            <izz>0.015</izz>
          </inertial>
        </inertial>
      </link>
    </model>
  </world>
```

## Testing Your Physics Simulation

To test your physics simulation:

1. Save your world file in `~/.gazebo/models` or in your custom directory
2. Launch Gazebo with your world: `gazebo your_world_file.world`
3. Observe the physics behavior of your objects
4. Adjust parameters as needed
