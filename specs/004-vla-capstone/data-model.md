# Data Model: Vision-Language-Action (VLA) Capstone

## Overview
This document defines the data models for the VLA Capstone module, including entities for voice commands, action sequences, multimodal inputs, and student learning paths. These models support the integration of voice, language, and action systems in the educational curriculum.

## Core Entities

### 1. VoiceCommand
Represents a voice command captured from the user and processed by the system.

**Fields:**
- `id` (string): Unique identifier for the command
- `audio_data` (bytes): Raw audio data captured from microphone
- `transcribed_text` (string): Text converted from speech using Whisper
- `intent` (string): Parsed intent extracted from the command
- `parameters` (object): Structured parameters extracted from the command
- `confidence` (float): Confidence score for the transcription (0-1)
- `timestamp` (datetime): When the command was captured
- `status` (enum): Status of the command processing (pending, processed, failed)

**Validation Rules:**
- `confidence` must be between 0 and 1
- `transcribed_text` must not be empty
- `intent` must be a recognized command type

### 2. ActionSequence
Represents a sequence of actions generated by the LLM from a voice command.

**Fields:**
- `id` (string): Unique identifier for the action sequence
- `voice_command_id` (string): Reference to the source voice command
- `sequence` (array): Ordered list of individual action steps
- `description` (string): Human-readable description of the sequence
- `status` (enum): Execution status (pending, in_progress, completed, failed)
- `created_at` (datetime): When the sequence was generated
- `executed_at` (datetime): When execution was completed

**Validation Rules:**
- `sequence` must contain at least one action
- Each action in `sequence` must be a valid ROS 2 action
- Status transitions must follow the expected flow

### 3. ActionStep
Represents a single step within an action sequence.

**Fields:**
- `id` (string): Unique identifier for the step
- `action_sequence_id` (string): Reference to the parent sequence
- `action_type` (enum): Type of action (navigation, manipulation, perception, etc.)
- `parameters` (object): Parameters specific to the action type
- `timeout` (integer): Maximum time to wait for action completion (seconds)
- `order` (integer): Order of this step in the sequence

**Validation Rules:**
- `action_type` must be a predefined valid action type
- `order` must be unique within the parent sequence
- `timeout` must be a positive integer

### 4. MultimodalInput
Represents combined input from multiple sensors (vision, voice, etc.).

**Fields:**
- `id` (string): Unique identifier for the multimodal input
- `voice_input_id` (string): Reference to the voice command
- `visual_data` (object): Visual input data (image, depth, etc.)
- `sensor_data` (object): Additional sensor inputs
- `fusion_result` (object): Combined result of multimodal processing
- `confidence` (float): Confidence in the fused interpretation (0-1)
- `timestamp` (datetime): When the input was captured

**Validation Rules:**
- `confidence` must be between 0 and 1
- Must have at least one of `voice_input_id` or `visual_data`

### 5. StudentLearningPath
Tracks the student's progress through the VLA module.

**Fields:**
- `id` (string): Unique identifier for the learning path
- `student_id` (string): Identifier for the student
- `module_progress` (object): Progress tracking for each module section
- `completed_chapters` (array): List of completed chapters
- `assessment_scores` (array): Scores for module assessments
- `start_date` (datetime): When the student started the module
- `completion_date` (datetime): When the student completed the module (if applicable)

**Validation Rules:**
- `student_id` must be unique
- Progress percentages must be between 0 and 100
- Assessment scores must be between 0 and 100

### 6. VLASystemState
Represents the current state of the VLA system during operation.

**Fields:**
- `id` (string): Unique identifier for the system state
- `current_voice_command` (string): Currently processed voice command
- `current_action_sequence` (string): Currently executing action sequence
- `robot_pose` (object): Current position and orientation of the robot
- `perception_data` (object): Current sensor and perception data
- `system_status` (enum): Overall system status (idle, listening, processing, executing)
- `last_update` (datetime): When the state was last updated

**Validation Rules:**
- `system_status` must be one of the predefined values
- `robot_pose` must contain position and orientation data when status is not idle

## Relationships

1. **VoiceCommand** → **ActionSequence** (1 to many)
   - One voice command can generate multiple action sequences (in case of retries or alternative plans)

2. **ActionSequence** → **ActionStep** (1 to many)
   - One action sequence consists of multiple ordered action steps

3. **VoiceCommand** → **MultimodalInput** (1 to 1)
   - Each voice command can be associated with a multimodal input

4. **StudentLearningPath** → **VoiceCommand** (1 to many)
   - Student learning path tracks multiple voice commands as they practice

## State Transitions

### VoiceCommand States
- `pending` → `processed` (when transcription and intent extraction complete)
- `pending` → `failed` (when processing fails)
- `processed` → `action_generated` (when LLM creates action sequence)

### ActionSequence States
- `pending` → `in_progress` (when execution starts)
- `in_progress` → `completed` (when all actions complete successfully)
- `in_progress` → `failed` (when an action fails)
- `in_progress` → `interrupted` (when a new command interrupts execution)

### VLASystemState Statuses
- `idle` → `listening` (when system starts listening for voice commands)
- `listening` → `processing` (when voice command is being processed)
- `processing` → `executing` (when action sequence is executing)
- `executing` → `idle` (when action sequence completes)
- `executing` → `error` (when system encounters an error)
